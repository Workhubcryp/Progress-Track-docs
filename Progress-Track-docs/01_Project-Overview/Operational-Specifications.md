# Project Milestones および README/ChangeLog - 索引 運用仕様書

```
本書は、プロジェクトにおける Project Milestones の蓄積、および 索引 README (ChangeLog) を管理する記述ルールと運用方法について定めたものである。
```
---

### 1. 目的と基本方針

- **運用の容易性**: 管理 No. による詳細記録と概要ログの紐づけ、タグ付けにより、日々の記録管理を容易にする。
- **一覧性と追跡性**: 索引 README/ChangeLog を一読するだけで、プロジェクトの大まかな作業ログ（チェンジログ）を追えるようにする。
- **検索性の担保**: 割り振られた管理 No. や Tag を用いて、詳細な作業記録 = Project Milestones（本文・個別ログ）を瞬時に検索・参照できるようにする。
- **RAG・検索最適化**: 将来的なRAG（検索拡張生成）による検索、Embedding、チャンク分割への影響を最適化するため、ファイル名は半角英数字（Alphanumeric）をベースとした命名規則に従う。

---

### 2. 構成とファイル配置

管理単位ごとに、以下の2階層で構成する。

- **プロジェクトルート/**
    - `Progress-Track-docs/`：詳細な作業記録を格納するディレクトリ
    - `README.md` ：本仕様に基づく README/ChangeLog - 索引
        - `[プロジェクト発生日]:ChangeLog 形式で記録概要のみを記載 - No./nnnn`：蓄積型の README.md に記載する索引 Log

---

### 3. Project Milestones の記述ルール

詳細な作業記録は、プロジェクト発生日をタイトル（ファイル名）とし、Title や管理用コードは半角英数字（Alphanumeric）をベースとした命名規則に従う。

---

### 4. 索引（README.md）の記述・運用ルール

README.mdは、詳細ログの概要のみを記載する「蓄積型のチェンジログ」として運用する。

### 4.1. 記載ルール

1. **新着最上位（降順）**: 新しい記録（新しいNo.）を上の行に追加する。
2. **管理No.の自動インクリメント**: 記載した順に連番（No.nnn1, No.nnn2...）を登録する。
3. **1行目の構成**: `[日付] 概要 <No.管理番号>` のフォーマットを厳守する。

### 4.2. 記載フォーマット

- １行目

```
[YYYY-MM-DD] [作業概要の簡潔な記述] No.[英数字のユニークなID]
Tag: 
	> 例: 本日の作業概要
	　　　 ・ 仕様書の新設
	      ・ Template 作成
	      ・ 記載ルールの制定
	      ・ README の作成
```

---

### 5. 検索・参照方法（運用の流れ）

1. **概要の把握**: `README.md` を上から順に読み、直近のプロジェクトの進捗や作業履歴の概要を追う。
2. **詳細の検索**: 特定の作業内容を詳しく知りたい場合、`README.md` に記載されている `No.nnn2` などの管理番号、または本文内の「タグ」でプロジェクト内を全文検索し、詳細ログファイル（本文）の該当箇所へダイレクトにジャンプする。
